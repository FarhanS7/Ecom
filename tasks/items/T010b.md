## Goal

Nest `AuthController` (`POST /v1/auth/register|login`) with cookie issuance
through the T006 problem contract, verified over real HTTP.

## Acceptance criteria

- [ ] Register → 201 + `authUser` (no hash) + `access_token`/`refresh_token`
  cookies (HttpOnly; SameSite per config; refresh path-scoped to `/v1/auth`);
  exactly one session family per call.
- [ ] Login → 200 + same; wrong password / unknown email / suspended →
  identical generic 401 (no existence disclosure); duplicate register → 409.
- [ ] Cookie flags inspected in tests; password hash absent from every body
  (asserted by scan, not by eye).
- [ ] Canonical spec: `apps/api/tests/integration/login.spec.ts` (needs real
  DB — skips honestly without; CI runs it live).
- [ ] Deferred visibly (not silently): CSRF/Origin checks (T013), rate limits
  (T013), gateway allowlist extension (T017 screens), email verification
  gating (T012). Register creates `active` users until T012 defines otherwise.

## Verification

API `build` + `typecheck` + `lint` + `test:integration` green; workspace gates green.
