## Goal and implementation steps

Turn runbook procedures into exercised drills for slow checkout, stock mismatch, queue backlog and payment uncertainty.

1. Read the linked module contract and relevant [architecture](../../ARCHITECTURE.md); identify the invariant this task changes. Write the failing scenario below before business logic.
2. Implement the smallest behavior that satisfies the acceptance criteria, using module ports and the transaction boundary where required. Keep unrelated changes out.
3. Run the focused verification, inspect actual behavior, and save evidence with the commit SHA. Record any justified contract change in the source ADR/spec before marking complete.
