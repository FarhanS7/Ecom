# T010a: Auth contracts and postgres identity service

Parent: [T010](T010.md). Created because T010 exceeds one focused session;
keep T010 as the parent ID per its scope rule.

- Module: [identity](../../docs/modules/identity.md)
- Phase: [Identity and stores](../phases/01-identity-stores.md)
- Dependencies: [T006](T006.md), [T009](T009.md)
- Branch: `feature/identity/t010-implement-registration-and-login` (shared with T010b)

## Goal

Auth DTOs/cookies contract plus the postgres-backed identity service:
normalization, argon2id, session-family issuance, generic failures, safe DTOs.

## Acceptance criteria

- [ ] `packages/contracts/src/identity.ts`: `authUser` (no hash), register/login
  shapes (drop the T002 `name` field — users table has no name column; record
  as change control), `authResponse` (no refresh token in body per ADR-0004;
  supersedes the unused T002 `tokenResponse`), cookie spec constants.
- [ ] `packages/backend/src/identity/auth.service.ts`: `normalizeEmail`,
  `hashPassword`/`verifyPassword` (argon2id), `registerAccount`,
  `authenticateAccount` (one transaction: user/family/token; duplicate → typed
  `ACCOUNT_EXISTS`; wrong creds/suspended → generic `INVALID_CREDENTIALS`),
  JWT access mint (sub/fid/roles, 15m), refresh issue (sha256 stored).
- [ ] Unit tests without DB: normalization vectors, argon2 round-trip +
  wrong-password rejection, JWT sign/verify round-trip, duplicate path via
  unique-violation mapping (unit-level, mock sql).

## Verification

Backend `build` + `typecheck` + `lint` + unit green. HTTP behavior belongs
to T010b. No migration (T009 tables final for this scope).
