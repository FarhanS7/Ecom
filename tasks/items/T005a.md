# T005a: Config module split and lazy database access

Parent: [T005](T005.md). Created because T005 exceeds one focused session;
keep T005 as the parent ID per its scope rule.

- Module: [platform](../../docs/modules/platform.md)
- Phase: [Foundation](../phases/00-foundation.md)
- Dependencies: [T003](T003.md)
- Branch: `feature/platform/t005-add-validated-configuration-and-health-routes` (shared with T005b)

## Goal

Split `packages/config/src/index.ts` into `env.ts` (schema + validation) with
`index.ts` as re-export only, and remove module-load side effects from the
database client so importing `@shopscale/backend` never throws on missing env.

## Acceptance criteria

- [ ] `packages/config/src/env.ts` owns `envSchema`/`getEnv`/`resetEnvCache`; `index.ts` re-exports only.
- [ ] No `getSql()`/`getEnv()` call at module top level in backend (`client.ts`,
  `platform/index.ts`, `db/seed.ts` use lazy accessors).
- [ ] Backend `build`, `typecheck`, and the T003 integration suite stay green.

## Verification

`pnpm --filter @shopscale/backend run build|typecheck|test:integration`.
A new unit assertion imports the backend root with empty env and expects no
throw at import time (connection still fails fast at first use, redacted).
