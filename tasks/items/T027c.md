# T027c: Seller console screens, routes, and batteries

Parent: [T027](T027.md) (split per its scope rule; T027 stays the parent ID).

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)
- Dependencies: [T027b](T027b.md)
- Branch: `feature/catalog/t027-build-seller-catalog-editing-screens`

## Goal

The screens named by the task (product editor, variant table, publication
controls) plus their routes, so a seller can author, publish per channel, and
archive a product.

## Acceptance criteria

- [x] `app/seller/[storeId]/layout.tsx`: resolves membership server-side; unknown
      store / non-member / no permission → one generic 404 (never a hint that the
      store exists); a guest gets a sign-in prompt instead of an empty console.
      The guest branch is proven in SSR (`next start` against a stub API answering
      only 401 → the sign-in prompt, and no product markup); the 404 branches are
      proven by the membership loader's unit tests and the API permission matrix
      (`apps/api/tests/integration/permission-matrix.spec.ts`, live DB in CI).
- [x] `app/seller/[storeId]/products/page.tsx`: server-rendered product list with
      each product's status and channel flags, plus the create form.
- [x] `app/seller/[storeId]/products/[productId]/page.tsx`: server-rendered
      editor (fields, variants, publication controls), uncached and scoped.
- [x] `product-form.tsx` (named `product-editor.tsx` in the plan; the screen is a
      form, so the file name follows that): labelled fields, a validation SUMMARY
      plus per-field errors, entered values preserved after rejection, and a
      conflict panel with "Reload latest" / "Apply my changes".
- [x] `variant-table.tsx`: list + inline add/edit (price in major units, SKU
      uniqueness surfaced as a conflict), every write carrying the product's
      version and adopting the new version from the response.
- [x] `publication-controls.tsx`: per-channel toggles (independent), publish,
      archive (terminal, confirmed inline), each with the honest reason when a
      transition is refused (e.g. no active variant).
- [x] jsdom tests for the three components plus the island that shares one product
      state (`product-workspace.test.tsx`), and
      `tests/e2e/seller-catalog.spec.ts` for the browser flow: create → publish →
      store-visible/marketplace-404 → marketplace opt-in → archive, plus a
      permission case (a member without catalog:manage cannot open the editor).
      The e2e spec needs a provisioned store member (`SELLER_E2E_*`) and browsers,
      so it is recorded as pending — see `docs/reviews/t027-context.md`.
- [x] `docs/reviews/t027-context.md` + `tasks/todo.md` updated.

## Verification

Web unit + lint + typecheck + build; SSR checks with `next start`; Playwright on
the bench host (recorded as pending when browsers/live DB are unavailable).
