## Goal

Store-scoped product/variant mutations with optimistic versioning and
explicit publication flags — no HTTP yet.

## Acceptance criteria

- [ ] `catalog/product.service.ts`: create/update/archive product
  (version check: stale expectedVersion → VERSION_CONFLICT, exactly one
  winner for two same-version writers), create/update variant (nonnegative
  price enforced by CHECK + contract), publication toggles update
  `product_publications` and bump product version in the same transaction.
- [ ] `contracts/src/catalog.ts`: zod request/response DTOs (money as
  nonnegative int cents; version fields explicit).
- [ ] Unit: version-conflict decision, money/DTO validation edges, archive
  semantics (archived product keeps variant rows — RESTRICT proven in T019
  integration; here DTO-level).
