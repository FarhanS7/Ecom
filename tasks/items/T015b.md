## Goal

Nest onboarding routes with admin/store scoping and the full acceptance flow
over real HTTP.

## Acceptance criteria

- [ ] `POST /v1/seller-applications` (auth) → business + pending store + owner
  membership + audit; second application → 409 (demo one-business rule).
- [ ] `POST /v1/admin/stores/{id}/approve|suspend` (platform admin only;
  store owner gets 403) with legal-transition enforcement + audit; suspend an
  approved store and assert scope state (membership reads still 200 — suspension
  gates publishing/checkout, not membership).
- [ ] Invitations: owner/manager (team:manage) creates; accept requires
  matching active account email; repeat accept → generic 404, single membership;
  cross-store role grant (A-owner patches B member) → 404.
- [ ] Member update with last-owner guard (demote/revoke last active owner → 409).
- [ ] Canonical spec `apps/api/tests/integration/onboarding.spec.ts` (real DB
  or honest skip) + `docs/openapi.json` regenerated (+6 paths).
