## Goal

Pure cursor encode/decode + filter fingerprint, and the keyset predicate
builder for the four closed sorts — no service wiring yet (T022b).

## Migration drift (recorded, not silently fixed)

T022's expected files name `db/migrations/0005-catalog-indexes.sql`. Two
problems: 0005 is taken (addresses), and the three indexes the data-model
plan named (`products(store_id,created_at DESC,id DESC)`,
`products(category_id,min_price_cents,id)`,
`products(category_id,sales_count DESC,id DESC)` partial-active) ALREADY
exist — T019 created them in `0006-catalog.sql`. No new migration is
added; per the design notes, non-schema tasks must not invent migrations.
If measurement (T078) shows a global-order index is needed for
marketplace-wide pagination, that is a measured addition then, not now.

## Acceptance criteria

- [ ] `catalog/cursor.ts`: opaque base64url cursor carrying version, sort,
  a filter+channel fingerprint, and the last `(sortValue, id)` tuple;
  decode rejects malformed base64/JSON, wrong version, missing fields,
  unknown sort, and over-long tuples.
- [ ] `catalog/list-query.ts`: closed per-sort keyset predicate
  (`(a,b) < (=) ($n,$n+1)` row comparison), order fragment, and the
  filter-fingerprint derivation; a cursor whose fingerprint differs from
  the request's channel/filters is a typed ERROR (wrong-channel and
  changed-filter cursors fail).
- [ ] Unit: codec round-trip, malformed rejection, fingerprint mismatch,
  predicate/order mapping, bounded limits.
