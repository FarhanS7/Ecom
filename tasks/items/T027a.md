# T027a: Publish transition and the seller lifecycle over real HTTP

Parent: [T027](T027.md) (split per its scope rule; T027 stays the parent ID).

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)
- Dependencies: [T020](T020.md)
- Branch: `feature/catalog/t027-build-seller-catalog-editing-screens`

## Goal

Make seller-authored products actually publishable, so T027's scenario
("create store-only, opt into marketplace, archive; verify public reads") is
reachable. Decision recorded in [ADR-0010](../../docs/decisions/0010-seller-catalog-publishing.md).

## Acceptance criteria

- [ ] `productUpdateRequest` accepts `status: 'draft' | 'active'` (never
      `archived`); contract tests cover accept/refuse.
- [ ] `updateProduct` applies the transition inside the versioned UPDATE, and
      activating requires ≥1 active variant — the guard runs after the UPDATE so
      a failure rolls back the whole transaction (no phantom version bump) and
      returns a constant 409.
- [ ] `min_price_cents` is refreshed when `status` is patched.
- [ ] The controller treats an unknown `status` value as malformed input (the
      route's generic 404), consistent with every other field.
- [ ] The live HTTP lifecycle test proves each public-read outcome: draft
      invisible everywhere → publish blocked without a variant → active
      store-only visible on the store channel and 404 in the marketplace →
      marketplace opt-in visible → marketplace unlisting keeps store visibility
      → archive invisible on both.
- [ ] `docs/modules/catalog.md` records the new invariant; no migration needed.
