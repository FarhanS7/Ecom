# T025a: URL filter state, the request contract, and the stale-request guard

Parent: [T025](T025.md). Created because T025 exceeds one focused session; keep
T025 as the parent ID per its scope rule.

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)
- Dependencies: [T022](T022.md), [T023](T023.md)
- Branch: `feature/catalog/t025-build-product-listing-and-filters`
  (shared with T025b)

## Goal

The pure layer behind the PLP: parse/serialize the filter state that lives in
the URL, build the gateway request in exactly one place (channel always in the
path), and offer a tested stale-request guard. No React yet (T025b).

## Acceptance criteria

- [ ] `features/catalog/query-state.ts`: URL ↔ filter state (`category`,
      `min`/`max` in MAJOR units, `sort`, cursor stack `after`) with strict
      validation (unknown sort → default; bad category/price/cursor → ignored
      or dropped, never sent upstream); canonical serialization; a 1-based
      page number derived from the cursor stack.
- [ ] `listApiPath` is the ONLY place the channel becomes a path, and a store
      channel with an empty slug THROWS instead of silently falling back to
      the marketplace endpoint (that fallback would leak marketplace data into
      a store page).
- [ ] `LatestRequest` guard: a newer `begin()` invalidates older tokens, so a
      slow response cannot overwrite a newer selection.
- [ ] Gateway allowlist gains catalog READ templates
      (`v1/catalog/marketplace/products`,
      `v1/catalog/stores/{slug}/products`) — the deferred T021b extension,
      now that a browser consumer exists. Templates are exact-shape, so
      `…/products/extra` and `v1/catalog/admin/products` stay rejected.
- [ ] Unit tests for every rule above.
