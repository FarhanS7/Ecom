## Goal

Framework-agnostic health logic in backend plus a thin Nest adapter in the API:
missing secrets stop boot; `/health/live` stays 200 during DB outage while
`/health/ready` reports degraded (HTTP 503); no secrets in any response.

## Acceptance criteria

- [ ] `packages/backend/src/platform/health.controller.ts` holds injectable,
  Nest-free health logic (liveness body, readiness aggregation → 200/503).
- [ ] `apps/api` exposes `GET /health/live` (200) and `GET /health/ready`
  (200 ok / 503 degraded) through a Nest controller; `main.ts` fails fast on
  missing secrets with a redacted error and imports `reflect-metadata`.
- [ ] HTTP-level tests cover valid boot, missing setting, and stopped DB
  (closed-port URL → fast refusal); responses validated against
  `@shopscale/contracts` health schemas; bodies asserted secret-free.

## Verification

`pnpm --filter @shopscale/api run test:integration` (real Nest + Fastify
`inject`, no network ports) plus workspace `build`/`typecheck`.
Canonical spec: `apps/api/tests/integration/health.spec.ts` (task suggested
root `tests/`; package-colocated per repo layout, as in T003).
