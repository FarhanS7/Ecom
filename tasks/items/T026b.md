# T026b: Product detail presentation, variant picker, and the route pair

Parent: [T026](T026.md). Created because T026 exceeds one focused session; keep
T026 as the parent ID per its scope rule.

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)
- Dependencies: [T026a](T026a.md)
- Branch: `feature/catalog/t026-build-product-detail-and-variant-selection`
  (shared with T026a)

## Goal

Render the PDP (`DESIGN.md` §7: media card beside an info card) for both
channels, with keyboard-operable variant selection that changes the displayed
price, and an honest purchase affordance.

## Acceptance criteria

- [ ] `variants.ts` (pure): variant labels (deterministic attribute order, SKU
      fallback), `resolveVariantId` (scoped to this product), and `purchaseState`
      — shared by the server route, the island, and the tests so the three
      cannot disagree.
- [ ] `variant-picker.tsx`: a native radio group (so arrow keys work for free)
      styled as pills, one option per API variant, labelled from its attributes
      with the SKU as the fallback; the group reflows away for a single-variant
      product; the selection writes `?variant=<id>` so a variant view is
      shareable and survives a reload.
- [ ] `product-detail.tsx`: media placeholder (neutral tile — media is T035, so
      no fake photo), title, selected variant price, description, attributes,
      store attribution, and one purchase control that is DISABLED with a single
      honest reason until inventory (T032) and the cart (T033) exist. The
      purchasable predicate is one function so those tasks flip it in one place.
- [ ] Routes `app/products/[slug]/page.tsx` and
      `app/stores/[slug]/products/[product]/page.tsx`: server-rendered detail
      from `loadProductDetail` with the route's channel; `not-found` → 404;
      `unavailable` → an honest 200 "temporarily unavailable" card (a 404 would
      assert non-existence, which an outage does not prove, and the unavailable
      response is identical for every slug so it reveals nothing about one
      product).
- [ ] Variant selection is validated against THIS product: an unknown or
      foreign `?variant=` id falls back to the first variant instead of
      rendering another product's price.
- [ ] `product-detail.test.tsx` / `variant-picker.test.tsx` (jsdom): selecting a
      variant changes the displayed price; the purchase control's disabled state
      follows the purchasable predicate; no-variant and unavailable fixtures
      render their honest states; `?variant=` seeding.
- [ ] `tests/e2e/product-detail.spec.ts`: keyboard variant selection changes the
      price (expected value read from the API, not copied from the component),
      the unavailable product fixture, server-rendered content, and
      channel-scoped requests for both routes. Honest skip when the bench
      database has no published product (T028 seeds one).

## Recorded deviation

The task's expected file list names `app/products/[id]/page.tsx`. The segment is
the product SLUG, not an id: the API's detail endpoint takes `:productSlug` (a
slug pattern), and T025's listing already emits `/products/{slug}`. Naming it
`[id]` would advertise a UUID the endpoint does not accept.

## Verification

the bench host. `t026-context.md` covers both subtasks.
