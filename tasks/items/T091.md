## Goal and implementation steps

Implement authenticated address creation, listing, editing and deletion with a small accessible account form. Checkout later reads an owned address and copies it into the order snapshot.

1. Add structured address validation and a user-owned table/migration.
2. Enforce owner scope on every read/write and return a safe address DTO.
3. Build an account address form with validation errors and keyboard support.
4. Verify foreign IDs are denied and editing an address cannot mutate historical order snapshots once checkout exists.

## Acceptance criteria

- [ ] A customer can create and select an address; required fields and length limits validate server-side.
- [ ] Another customer cannot read/update/delete it by ID. Deleting an address leaves already-created order snapshots intact.
- [ ] The real API/browser flow works, and invalid input preserves entered form values with accessible errors.

## Verification

Create address A for customer 1, attempt read/update/delete as customer 2, then update A as its owner. Once T047 exists, place an order, change/delete A and verify its historical delivery snapshot remains unchanged.

## Design and review notes

Addresses belong to a user, not to the store where they are used. Seller staff receive a paid order's scoped delivery snapshot, never unrestricted access to the customer's address book. No external address-verification provider is required for the demo. DSA: not a separate algorithm exercise; ownership and snapshot semantics are the important checks.
