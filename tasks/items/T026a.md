## Goal

One place that maps a channel + product slug to a detail request, and a
server-only loader that turns the API's answer into exactly three honest
outcomes: `ok`, `not-found`, `unavailable`.

## Acceptance criteria

- [ ] `productUpstreamPath(channel, productSlug)` is the single channel→path
      mapping for detail reads (mirrors `listUpstreamPath`, throws on an empty
      store slug or a slug that is not the API's product-slug shape), so a store
      page can never fetch the marketplace's copy.
- [ ] `loadProductDetail(storeSlug, productSlug)` (server-only) memoizes per
      request on PRIMITIVE arguments, so it cannot collide between the
      marketplace and a store, or between two stores, and a second caller in the
      same request (page + metadata) reuses one fetch.
- [ ] Outcomes: API 404 or a malformed slug → `not-found`; network failure,
      non-404 error status, or a body that fails `channelProductDetail` →
      `unavailable`. No path renders an outage as "this product does not exist".
- [ ] Called with `cache: 'no-store'` so a product response is never reused
      across requests.
- [ ] Tests for the path builder (channel scoping + refusals) and the loader
      (404, 500, throw, malformed body, ok, and the exact URL it requested).
- [ ] No gateway allowlist entry is added: nothing in the browser fetches a
      product detail, so the same-origin allowlist stays minimal.
