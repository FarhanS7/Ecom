## Goal

Pill filter controls + the client listing island (loading/error/empty/race
states) wired into the marketplace PLP (`/products`) and the store PLP
(`/stores/{slug}/products`), then the e2e battery.

## Acceptance criteria

- [ ] `features/catalog/filter-panel.tsx`: sort pills, price min/max pills,
      category pill, clear-filters — every change writes the URL (so the URL is
      the single source of truth and back/forward restores filters); empty
      blocks reflow; controls are keyboard operable with the design focus ring.
- [ ] `features/catalog/product-list.tsx`: fetches through the same-origin
      gateway using `listRequestUrl` (channel always in the path), one in-flight
      request at a time, an abort + `LatestRequest` guard so an out-of-order
      response cannot overwrite a newer selection; skeleton loading (never a
      spinner inside a card), error + retry, honest empty state, cursor
      pagination (Next appends to the cursor stack, Previous pops), and the
      URL-links only use `listHref`.
- [ ] Routes `app/products/page.tsx` and `app/stores/[slug]/products/page.tsx`
      render the frame/header + filter panel + island; the store PLP resolves
      the channel from the path (unknown store → 404) and passes the store
      channel so every request stays store-scoped.
- [ ] `product-list.test.tsx` (jsdom): out-of-order responses keep the newest
      selection; error → retry recovers; empty result renders the honest empty
      state; skeletons while loading; pagination links carry the cursor stack
      and the filters.
- [ ] `tests/e2e/product-list.spec.ts`: mobile + desktop filter navigation,
      back/forward restoration, empty results, and API-failure state. Bench
      host only — honest skip where browsers are absent.

## Recorded limitation

The PLP exposes both price and category filters plus the empty/error states the
acceptance describes; category filtering is URL/deep-link driven (there is no
public categories endpoint yet), and the price/category inputs work without
chips. The listing itself is a client island (the architecture assigns filters
to client components), so without JavaScript the PLP shows its loading state
rather than server-rendered products — recorded as a known limitation with the
reason, not claimed as covered.
