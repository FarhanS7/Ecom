## Goal

Enforce limits + origin checks on auth mutations, safe headers on all API
responses, and a same-origin client helper — proven over real HTTP.

## Acceptance criteria

- [ ] Login/register/refresh: Origin check (mismatch → 403, absent → allowed
  per documented rationale), IP + email/token budgets (exceeded → 429 with
  `Retry-After` + RATE_LIMITED problem), limiter down → 503 fail-closed.
- [ ] `onSend` security headers on every API response (asserted).
- [ ] `apps/web/src/lib/csrf.ts`: same-origin-only POST helper
  (absolute URLs rejected pre-fetch, `credentials: same-origin`), unit-tested.
- [ ] Canonical spec `apps/api/tests/integration/auth-security.spec.ts`:
  threshold→429 with header, cooldown covered at unit level, wrong-origin 403,
  unavailable→503, headers present. Uses injected fake counters with PRODUCTION
  policy constants (fast, deterministic); live-Redis cycle runs only where the
  cache connects (CI), skips otherwise.
- [ ] No new routes → no openapi regen needed (recorded).
