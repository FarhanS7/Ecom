## Goal

The deterministic foundation the whole seed stands on: a seeded random source, a
*name-addressed* id scheme (so a new row never shifts the ids of existing rows),
explicit seed-derived timestamps, and the identity/store fixtures — including the
two fixtures the acceptance criteria name: a registered account that owns
nothing, and scoped staff with exactly the documented role grants.

## Files (layout deviation, recorded)

The task file suggests `db/seed/*.ts`. `db/` holds reviewed SQL and the Drizzle
config only and is outside every tsconfig and the lint glob, so generators placed
there could not be typechecked or linted. The generators live in
`packages/backend/src/db/seed/` instead, next to the existing `db/seed.ts`
entrypoint. Everything else follows the suggested names.

## Acceptance criteria

- [ ] `random.ts`: `seedRandom(seed)` (documented PRNG), `uuidV5(name)` under a
      fixed project namespace, `intBetween`, `pick`, `weighted`, `logNormal`,
      `isoFromSeed`. All pure; no DB, no `Math.random`, no `Date.now`.
- [ ] `uuidV5` matches the RFC 4122 test vectors the unit suite pins, and ids are
      stable when generation order changes (`uuidV5('product:a:1')` never moves
      because a product was added elsewhere).
- [ ] `identity.ts`: `planIdentity(options)` returns plain rows — users (platform
      admin, an **empty account** with no business/store/membership, one owner per
      store, scoped staff, and a non-member), businesses (one per store, D-007),
      stores with `seed-` slugs, and memberships whose roles mirror
      `STORE_ROLE_GRANTS`.
- [ ] The empty account is provably empty: the plan contains its user row and no
      store, membership, or business that references it.
- [ ] Staff scope is exact: `catalog-editor` holds `catalog:manage` and NOT
      `fulfillment:manage`; `fulfillment` the reverse; the non-member holds
      nothing anywhere.
- [ ] Timestamps come from the seed (a fixed epoch minus deterministic offsets),
      so two runs of the same seed produce byte-identical rows.
- [ ] `seed.ts` accepts the documented CLI shape (`--size s --seed 42`, env
      fallback), refuses sizes above `s` with an explicit "T077 owns the streaming
      sizes" message instead of pretending, refuses to run against a production
      database without an explicit override, and never prints credentials.
- [ ] Root `pnpm seed` script exists; `seed:verify` lands with T028b's `verify.ts`.
