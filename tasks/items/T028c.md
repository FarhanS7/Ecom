# T028c: Live seed verification and evidence

Parent: [T028](T028.md) (split per its scope rule; T028 stays the parent ID).

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)

- Branch: `feature/catalog/t028-seed-a-deterministic-catalog-skeleton`

## Goal

The acceptance scenario itself, against real PostgreSQL: seed, seed again, and
prove that the two runs are the same dataset — then prove it is a *valid*
dataset (every FK holds) and a *browsable* one (the catalog read service returns
the seeded products per channel).

## Acceptance criteria

- [ ] `packages/backend/tests/integration/catalog-seed.spec.ts` (the task file's
      `tests/integration/catalog-seed.spec.ts`, which is this path) skips honestly
      without a live DB and runs in CI.
- [ ] **Idempotence:** seeding twice without wiping leaves every count unchanged
      and every checksum unchanged.
- [ ] **Reproducibility:** after a wipe, a second run with the same seed produces
      the same ids and the same checksums; `SEED=43` produces different ones.
- [ ] **Referential integrity:** every FK is checked live (variants → products with
      the store composite FK, publications → products, products → stores and
      categories, memberships → stores/users/roles, themes/content → stores, and
      `businesses` one-per-store).
- [ ] **Storefront browsing:** the marketplace channel and a store channel each
      return the seeded, published products through the real read service, the
      empty store returns none without erroring, and a channel-disabled product is
      absent.
- [ ] The isolated data is removed afterwards (scoped to the `seed-` markers), so
      the suite stays re-runnable and cannot disturb the other specs' fixtures.
- [ ] The task file's `pnpm exec jest …` command is recorded as superseded:
      vitest is the runner (`docs/operations/commands.md`), so the spec runs under
      `vitest --config vitest.integration.config.ts`.
- [ ] `docs/reviews/t028-context.md` and `tasks/todo.md` updated; live-DB evidence
      recorded honestly (this host has no Postgres, so the run is a declared
      pending for CI unless infra is available).
