# T028c: Live seed verification and evidence

## Goal

The acceptance scenario itself, against real PostgreSQL: seed, seed again, and
prove that the two runs are the same dataset — then prove it is a *valid*
dataset (every FK holds) and a *browsable* one (the catalog read service returns
the seeded products per channel).

## Acceptance criteria

- [x] `packages/backend/tests/integration/catalog-seed.spec.ts` (the task file's
      `tests/integration/catalog-seed.spec.ts`, which is this path) skips honestly
      without a live DB and runs in CI.
- [x] **Idempotence:** seeding twice without wiping leaves every count unchanged
      and every checksum unchanged — asserted in the spec, and observed through the
      real CLI (`pnpm seed --size s --seed 42` twice: the second run inserted 0 rows
      in every table and reported the same plan and database checksums).
- [x] **Reproducibility:** after a wipe, a second run with the same seed produces
      the same ids and the same checksums; `SEED=43` produces different ones.
- [x] **Referential integrity:** all 15 named FK checks run live and report 0
      orphans (variants → products with the store composite FK, publications →
      products, products → stores and categories, memberships → stores/users/roles,
      themes/content → stores, and `businesses` one-per-store).
- [x] **Storefront browsing:** the marketplace channel and a store channel each
      return the seeded, published products through the real read service, the
      empty store returns none without erroring, a channel-disabled product is
      absent, a flagged draft and an archived product are absent from both channels
      despite their publication flags, and a slug shared with another store never
      leaks across the store boundary.
- [x] The isolated data is removed afterwards (scoped to the `seed-` markers), so
      the suite stays re-runnable and cannot disturb the other specs' fixtures.
- [x] The task file's `pnpm exec jest …` command is recorded as superseded:
      vitest is the runner (`docs/operations/commands.md`), so the spec runs under
      `vitest --config vitest.integration.config.ts`.
- [x] `docs/reviews/t028-context.md` and `tasks/todo.md` updated, with the live
      evidence recorded honestly. A live database WAS obtained on this host (a
      throwaway PostgreSQL 17 cluster on port 55432 — never the user's instance), so
      the live run is reported as executed, not as a pending. Both the backend and
      the API integration suites ran green live (10 files / 23 tests and 12 files /
      50 tests, no SKIP lines); Playwright, CI and the independent review remain
      declared pendings.

## Verification

```powershell
pnpm --filter @shopscale/backend exec vitest run --config vitest.integration.config.ts tests/integration/catalog-seed.spec.ts
pnpm --filter=@shopscale/backend run test:unit
pnpm lint; pnpm typecheck; pnpm build
```

Observed on this host against the throwaway cluster: backend unit 22 files / 122
tests; backend integration 10 files / 23 tests (all live, no SKIP lines); backend
typecheck, backend build and root lint exit 0; `pnpm seed --size s --seed 42` →
1000 products / 2512 variants / 15 FK checks / verification passed, second run 0
inserted with identical checksums. Details and the five defects the live run found
are in `docs/reviews/t028-context.md`.
