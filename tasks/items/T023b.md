## Goal

The reusable primitive set named in DESIGN.md §11 and the architecture's
design-system list: `Frame`, `Header`, `SearchPill`, `IconCircleButton`,
`Card`, `Tag`, `RatingBadge`, `PrimaryButton`, `ArrowButton`, `SocialRow`,
plus pill `Input`/`Field` form primitives. Wire the tenant mapping from
T023a into the storefront layout. Component state tests + an e2e spec.

## Acceptance criteria

- [ ] `apps/web/src/components/ui.tsx`: primitives read colors/radii only
  from tokens (no hard-coded hex in components); every icon-only control has
  `aria-label`; arrow buttons carry the ↗ glyph; one accent CTA shape.
- [ ] `apps/web/src/components/header.tsx`: floating pill header (56px,
  logo + search pill + cart/wishlist/account circles, sticky), signed-out
  "Sign in" variant.
- [ ] `apps/web/src/app/stores/[slug]/layout.tsx` uses `tenantThemeStyle` +
  `data-tenant` (replacing the inline `themeVars`); `data-testid="store-theme"`
  and the `#111111`/`#222222` style contract keep working.
- [ ] `apps/web/src/components/ui.test.tsx` (jsdom): component STATE tests —
  disabled/loading, labelled icon buttons, eyebrow+headline structure,
  sign-in vs account variant, form error announcement, empty-block reflow.
- [ ] `tests/e2e/design-system.spec.ts`: 390/768/1024/1440 screenshots and
  both seeded themes; CI-live on the bench host, honest skip where browsers
  are absent (no browsers on the agent host).
