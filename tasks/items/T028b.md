# T028b: Catalog, theme, and publication generators plus verification

Parent: [T028](T028.md) (split per its scope rule; T028 stays the parent ID).

- Module: [catalog](../../docs/modules/catalog.md)
- Phase: [Catalog and storefront](../phases/02-catalog-storefront.md)
- Dependencies: [T028a](T028a.md)
- Branch: `feature/catalog/t028-seed-a-deterministic-catalog-skeleton`

## Goal

A Tier S catalog that a human can actually browse: a category tree, products with
variants and prices, per-channel publication that agrees with product status, a
validated theme per store, and a verifier that can state what was seeded.

## Acceptance criteria

- [ ] `catalog.ts`: `planCatalog(identity, options)` returns plain rows for
      categories (a real tree with `/parent/child/` paths), products (unique slug
      per store, `seed-` prefixed, deterministic ids), variants (active and
      inactive, log-normal prices), and publications.
- [ ] `min_price_cents` equals the cheapest ACTIVE variant's price — derived, never
      an independent random number (the T019 invariant).
- [ ] Publication agrees with status by construction: only `active` products may
      carry a channel flag, and the plan contains one store where an enabled flag
      on a draft product proves the "on (not live)" case, plus one active-only and
      one empty store so the storefront's visible/partial/empty paths are covered.
- [ ] `themes.ts`: theme tokens per store validated against the shared contract
      (`storeTheme`), plus `store_content` whose `featured_ids` reference products
      of THAT store, deterministically.
- [ ] `verify.ts`: `checksum(plan)` — a stable digest over the domain columns only
      (never `password_hash`, never a token hash) — plus `verifyDatabase(sql)`
      returning per-table counts, FK-clean results, and distribution facts.
- [ ] `seed.ts` writes the plan in FK order inside bounded chunks, idempotently
      (`ON CONFLICT DO NOTHING` on the deterministic PKs), so a second run changes
      no row and duplicates nothing.
- [ ] Root `pnpm seed:verify` script exists and reports counts/FKs/distributions.
- [ ] Unit tests for the pure planners: determinism (same seed → same plan and
      same checksum), sensitivity (a different seed → a different checksum),
      scoped-unique slugs/SKUs, derived `min_price_cents`, and published-implies-
      active.
- [ ] The commands doc line for `seed:verify` ("counts/FKs/distributions/ledger")
      is honoured for counts/FKs/distributions; the ledger half is recorded as not
      applicable until orders exist (T077).
