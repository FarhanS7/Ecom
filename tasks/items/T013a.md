# T013a: Rate limiter and origin/security helpers (pure + fakes)

Parent: [T013](T013.md). Created because T013 exceeds one focused session;
keep T013 as the parent ID per its scope rule.

- Module: [identity](../../docs/modules/identity.md)
- Phase: [Identity and stores](../phases/01-identity-stores.md)
- Dependencies: [T011](T011.md)
- Branch: `feature/identity/t013-auth-throttling-and-browser-protections` (shared with T013b)

## Goal

Redis-backed fixed-window limiter with explicit fail-closed semantics, plus
same-origin verification and the safe-headers map — all unit-proven without
infrastructure.

## Acceptance criteria

- [ ] `identity/rate-limit.ts`: atomic Lua consume (INCR + first-write EXPIRE +
  PTTL), `RateLimited`/`LimiterUnavailable` typed outcomes, documented policies
  (login/register: 20/60s per IP, 10/60s per email; refresh: 20/60s per IP,
  30/60s per token hash), lazy singleton on `REDIS_CACHE_URL`, documented test
  seam. Windows expire — nothing is ever permanently locked out.
- [ ] `platform/security.ts`: `SECURITY_HEADERS` map, `isSameOriginRequest`
  (present Origin/Referer must match host; absent allowed with documented
  rationale: browsers always send Origin on cookie POSTs).
- [ ] Unit tests: threshold deny, per-key isolation, window reset via manual
  fake clock (no sleeps), unavailable → typed throw, origin table, header map.

## Verification

Backend `build` + `typecheck` + `lint` + unit green. Live-Redis proof is T013b
(optional live test: runs wherever REDIS_CACHE_URL connects, skips otherwise).
