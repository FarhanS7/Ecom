# T017a: Gateway auth support (POST, session cookies, Set-Cookie)

Parent: [T017](T017.md). Created because T017 exceeds one focused session;
keep T017 as the parent ID per its scope rule.

- Module: [identity](../../docs/modules/identity.md)
- Phase: [Identity and stores](../phases/01-identity-stores.md)
- Dependencies: [T010](T010.md), [T011](T011.md), [T012](T012.md), [T013](T013.md)
- Branch: `feature/identity/t017-build-account-and-recovery-screens` (shared with T017b)

## Goal

Extend the same-origin gateway so browser auth flows work end to end: POST
support, auth-path allowlist, session-cookie forwarding (allowlisted names
only), and Set-Cookie passthrough — without weakening any T007a guarantee.

## Acceptance criteria

- [ ] Allowlist += auth paths (register/login/refresh/logout/me,
  password-reset/*, verify-email/*); everything else still 404s.
- [ ] `Cookie` forwarding restricted to `access_token`/`refresh_token` exact
  names (rebuilt header, never blind passthrough); all `Set-Cookie` response
  headers forwarded with statuses preserved.
- [ ] Upstream Origin absence unchanged (server-to-server has no Origin; the
  API's absent-origin rule already covers it — no new hole).
- [ ] No `Authorization` header or arbitrary-cookie forwarding, ever.

## Verification

Prod loopback battery: cookie round-trip (login sets pair through gateway;
`/api/v1/auth/me` with cookies → 200; unknown route still 404; foreign
cookies dropped — asserted by echo inspection). Bundle impact: none (server
route only).
